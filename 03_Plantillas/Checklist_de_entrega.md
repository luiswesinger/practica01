# Checklist de entrega · SmartCampus

Marcación orientativa para el equipo; los criterios oficiales están en el enunciado.

- [ ] Repositorio GitHub accesible para corrección y enlace listo para entregar.
- [ ] `docker-compose.yml` y Dockerfile(s)/configuración, según la implementación.
- [ ] Servicios Jupyter, PostgreSQL y Flask conectados entre sí.
- [ ] Persistencia de PostgreSQL comprobada.
- [ ] Notebook con importación de `sensores.csv` y carga de datos.
- [ ] Consultas y análisis en PostgreSQL y SQLite, reutilizando lógica.
- [ ] API: `GET /health`, `GET /lecturas` y `POST /lecturas`.
- [ ] API: error HTTP 400 al faltar un campo obligatorio.
- [ ] Prueba desde Jupyter: `POST` + confirmación de lectura en PostgreSQL.
- [ ] Capturas técnicas: servicios, bases de datos, API e integración.
- [ ] README propio con instrucciones suficientes para reproducir el proyecto.
- [ ] Memoria de IA: todas las capturas de los prompts y respuestas, incluidos fallos; finalidades, correcciones, validación y balance; **o declaración de no uso de IA**.
- [ ] Sin contraseñas, secretos, datos personales ni información confidencial en GitHub o en evidencias.
- [ ] Bonus realizados documentados, si procede.
